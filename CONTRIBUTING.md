# Contributing

Thanks for helping improve Sanam Knowledge Graph.

The goal of `main` is to remain a **generic, reusable knowledge framework** that anyone can fork.

## What belongs in contributions

Good contributions include:

- better reusable templates
- clearer documentation
- improved learning/knowledge structures
- accessibility or usability improvements
- optional tooling that does not make Markdown/Git unusable on its own
- fixes to confusing or inconsistent framework behavior

## What does not belong on main

Please do not submit:

- your personal knowledge map
- personal goals or private reflections
- credentials or secrets
- confidential work information
- content copied from sources without permission
- framework complexity without a clear benefit

Your own knowledge should live in your fork or personal branch.

## Suggested workflow

1. Fork the repository.
2. Create a branch for your framework change.
3. Make one focused improvement.
4. Check that the generic templates still make sense for a new user.
5. Open a pull request explaining the problem and the change.

## Design principles

Framework changes should preserve these qualities:

- simple
- readable
- honest
- portable
- Git-friendly
- useful without custom software
- easy to fork
- easy to extend

## Pull requests

Keep pull requests focused.

Please describe:

- what problem you are solving
- what you changed
- why the change belongs in the reusable framework
- any trade-offs or migration impact
